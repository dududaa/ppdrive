# v0.3.3 — Self-Update Works While Running

## Bug Fixes

- **`ppdrive update` no longer fails with `Error: Text file busy (os error 26)`** — the updater wrote over the running executables in place, which Linux rejects with `ETXTBSY` (it always overwrites its own `ppdrive` binary, and a running `server` blocks the server binary). Binaries are now staged as `<name>.new` and atomically renamed into place: existing processes keep the old code until restarted, and a failed update leaves the previous binaries untouched.
- **Plugin downloads stage to `.part` before replacing** — `ppdrive plugin add` / `update` no longer risk the same `Text file busy` error when the server has the library loaded, and an interrupted download can never truncate an installed plugin or the media runtime bundle.

## Upgrade Notes

- The updater that ships in **v0.3.1 and v0.3.2 is affected** and cannot fix itself: migrate once by hand — stop the server, extract the release tarball over the install directory, start the server. Every later `ppdrive update` works, including with the server running.

## Internal

- Workspace version moved to `0.3.3`.
- Regression tests: staged rename succeeds over a running executable (while plain copy fails with `ETXTBSY`), failure cleans staging and preserves the destination, and content swap is verified.
