# v0.3.2 — Network Bind Control, Shared Media Runtime

## Features

- **`ppdrive serve --host <ADDR>`** — choose the address the server binds:
  - The default bind is now **`127.0.0.1`** (loopback only) instead of `0.0.0.0`. `ppdrive serve --host 0.0.0.0` temporarily exposes the server to every device on your network; a specific interface IP (`--host 192.168.1.20`), a hostname or an IPv6 literal (`--host ::1`) also work. The `server` binary accepts the same flag, and bind failures report `failed to bind <host>:<port>`.
  - **Breaking**: deployments that relied on implicit LAN access must now pass `--host 0.0.0.0`. The Docker image runs `server --host 0.0.0.0` so `docker run -p` publishing is unaffected, and reverse-proxy setups (nginx → `127.0.0.1:8000`) now match the default.
- **Media plugins use a shared FFmpeg runtime** — prebuilt `dududaa/ppff` plugins no longer carry a private copy of FFmpeg (~40 MB each). `ppdrive plugin add` / `update` now installs one `ppdrive-media-runtime-<os>-<arch>.tar.gz` bundle from the same release into `libs/`, where every installed plugin resolves it through its own directory (on Windows the loader opens plugins with `LOAD_WITH_ALTERED_SEARCH_PATH`). Plugins themselves shrink to under 1 MB, and all of them share a single FFmpeg mapping in the server process. Releases predating the runtime bundle (static plugins) install nothing extra.

## Documentation

- `cli/serve` documents `--host` with a LAN example and a firewall/CORS note, and drops the stale claim that `ppdrive serve <PORT>` accepts a positional port.
- `deployment/production` and `deployment/docker` note the loopback default behind reverse proxies and the container `--host 0.0.0.0` override; `cli/overview` shows the LAN example.
- `PLUGIN.MD` covers the shared media runtime bundle.

## Internal

- Workspace version moved to `0.3.2`.
- Server bind-argument parsing (`parse_bind_args`, 7 tests) and CLI `--host` parsing (3 tests) are unit-tested; the e2e suite and docs build are unchanged and green.
