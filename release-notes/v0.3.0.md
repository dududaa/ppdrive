# v0.3.0 — Audio & Video Post-Processing, Transformed Downloads

## Features

- **Transformed downloads** — apply `image_transformation` on the fly when serving downloads:
  - **Signed downloads**: pass `image_transformation` in the download-sign request; it is validated at sign time (operation arguments, `image/*` source requirement, plugin availability) and embedded in the signed token, so every download with that token serves the rendition.
  - **Direct downloads**: append `?image_transformation=<url-encoded JSON>` to a public/static download URL.
  - Transformed responses are cached in the message broker (`transform_cache_ttl_secs`, default `86400`; `transform_cache_max_age_secs`, default `3600`, capped by a signed token's remaining lifetime).
- **Plugin activation control** — registry plugins carry an `active` flag:
  - `ppdrive plugin activate <ID>` / `ppdrive plugin deactivate <ID>`; the server loads only active plugins, and `plugin update` preserves the activation state.
  - Session gates distinguish *not installed*, *deactivated* (with the exact `ppdrive plugin activate <id>` hint) and *failed to load*.
- **Audio post-processing** — `audio_conversion` and `audio_effects` upload session options:
  - Conversion formats Wav/Mp3/Flac/Aac/Ogg/Opus with a quality → bitrate ladder, `sample_rate` and `channels`; effects operations `volume`, `fade`, `speed`, `bass`, `treble`, `echo`, `trim`, `reverse`, `normalize`, plus a raw FFmpeg `custom_filters` escape hatch.
  - Output path and `content_type` are rewritten at session creation; effects run before conversion when both are set; inline or background via `audio_conversion_background` / `audio_effects_background`.
- **Media streaming** — the `media_streaming` upload session option packages uploads into adaptive HLS or DASH:
  - `protocol` (hls/dash), `segment_duration`, `quality` and a `renditions` ladder; audio-only inputs get a single audio rendition.
  - File-based dispatch writes to a sidecar `<path>.stream/` or a bucket-contained `output_dir` (no traversal, must not contain the upload path); `delete_source` defaults to `true`, so the registered asset points at the master playlist (`master.m3u8` / `manifest.mpd`).
  - Gated on a `video/*` or `audio/*` `content_type` with session-time rendition/output_dir validation; inline or background via `media_streaming_background`.
- **Video conversion and transformation** — `video_conversion` and `video_transformation` upload session options:
  - Conversion: ten container/codec targets (MP4/WebM/MOV/MKV/AVI × H.264/VP9/AV1/H.265), quality → CRF mapping, `width`/`height`/`scale`, `effort`, `max_bytes` size search, constant `fps`, `drop_audio` and `keyframe_interval`.
  - Transformation: typed operations (`crop`, `scale`, `rotate`, `flip`, `grayscale`, `adjust`, `blur`, `sharpen`, `pad`, `trim`, `speed`, `reverse`) plus raw `custom_filters`, with an optional output `format`.
  - Paths and `content_type` are rewritten at session creation (always for conversion; for transformation only when `format` is set), the chain runs transform → convert, and either option can run background via `video_conversion_background` / `video_transformation_background`.
- **`image-compression` renamed to `image-conversion`** — the session option, config knob (`image_conversion_background`) and plugin id follow the upstream rename, and the option gains `scale`, `effort` and `max_bytes`. Serde aliases keep existing request bodies, signed session tokens and `ppd_config.toml` files working.
- **Local plugin builds** — `ppdrive plugin add <ID> --source <DIR> --local --build` compiles a local source directory and reports cargo's captured stderr on failure; the build targets the plugin's own cargo package (`ppdrive-<id>`), matching the upstream layout.

## Breaking Changes

- **Plugin id `image-compression` → `image-conversion`** — registry entries recorded as `image-compression` are no longer loaded (clean break): remove and re-add the plugin (`ppdrive plugin remove image-compression` then `ppdrive plugin add image-conversion ...`). Request bodies, signed session tokens and config files keep working through aliases.
- **Deactivated plugins fail fast** — upload sessions that use a deactivated plugin are rejected with `400 <id> plugin is installed but deactivated; run \`ppdrive plugin activate <id>\`` at session creation instead of failing later.

## Upgrade Notes

- Re-register the image plugin as `image-conversion` if you had `image-compression` installed (above).
- Install and activate the plugins for the features you use: `audio-conversion`, `audio-effects`, `media-streaming`, `video-conversion`, `video-transformation` — each session option requires its plugin to be installed **and** active.
- `media_streaming` deletes the source file by default once the package is written; set `delete_source: false` to keep the original.

## Bug Fixes

- First-run uploads no longer fail when the storage root does not exist yet: the directory is created before the path is canonicalized (`root_dir = "storage"` on a fresh checkout included).
- Overwrite uploads into buckets no longer `500` on `UNIQUE (bucket_id, path)`: asset registration reuses the existing row, keeping asset identity and grants stable.
- Bucket creation returns typed errors instead of a generic `Bucket creation failed` `500`: `403` for foreign owners, `409` for duplicate paths, static-folder conflicts and privacy mismatches, `500` only for real failures.
- Public-bucket and static-folder mount roots resolve via `root_dir` instead of the executable directory, so configured storage roots serve correctly.
- The rate limiter emits its response headers — `x-ratelimit-limit`, `x-ratelimit-remaining`, plus `retry-after` and `x-ratelimit-after` on `429` — and the upload docs document the real names.
