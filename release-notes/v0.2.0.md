# v0.2.0 — Plugin System & Image Processing

## Features

- **Plugin system** — PPDRIVE can now be extended with dynamically loaded native plugins (`.so` libraries):
  - `ppdrive plugin add <id> --source <repo|path>` installs plugins from a remote repository (`github:owner/repo`, git URL) or a local file/source directory; `--build` compiles Rust sources with `cargo build --release --lib`.
  - `ppdrive plugin list` / `remove` / `update [id]` manage the registry; `update` refreshes one or all installed plugins from their recorded source.
  - Plugin entries record source metadata (`source`, `build`) so updates can rebuild or re-download automatically.
  - **Hyphenated ids everywhere**: the stored short id (`image-compression`), the full id (`ppdrive-image-compression`), the cargo package (`ppdrive-image-compression`) and the release asset (`ppdrive-image-compression-linux-x86_64.so`) follow one convention; the legacy `ppdrive_`/`_` forms are still accepted on input and are normalized, and existing registries are migrated on load.
  - Plugin libraries stay loaded for the server's lifetime; responses are dispatched through a non-generic dispatcher that owns the plugin handle, eliminating use-after-free risks from temporary loaders.
- **Image compression on upload** — optional `image_compression` session config compresses uploads through the `image-compression` plugin (format, quality, max width/height), with path/content-type rewriting to the output format and inline or background processing.
- **Image transformation on upload** — optional `image_transformation` session config applies typed operations (crop, rotate, flip, pad, grayscale, adjust, blur, sharpen, scale) or raw FFmpeg filters through the `image-transformation` plugin, before compression when both are set.
- **Background processing controls** — `image_compression_background` / `image_transformation_background` config fields (overridable per upload) send the response before post-processing runs.
- **`mounted_devices()`** — system info now reports mounted filesystems on Linux, macOS, BSD and Windows.

## Upgrade Notes

- **Release assets are renamed** to the `ppdrive-server-<os>-<arch>.<ext>` convention (e.g. `ppdrive-server-linux-x86_64.tar.gz`, `ppdrive-server-macos-aarch64.tar.gz`). `install.sh`, `install.ps1` and `ppdrive update` all download the new names.
- `ppdrive update` from v0.1.5 or older still looks for the old asset names (`ppdrive-linux.tar.gz`, …) and cannot download this release. Update once with `curl -fsSL https://raw.githubusercontent.com/dududaa/ppdrive/main/install.sh | bash` (or download manually); subsequent `ppdrive update` runs work normally.

## Bug Fixes

- Plugin `.so` files are kept loaded for the whole server lifetime instead of being unloaded between requests.
- Plugin registry loads cleanly regardless of whether ids are stored in short or legacy full form.

## Documentation

- Installation and Update docs updated to the renamed release assets.
- README roadmap restructured with a media extension group; image compression and transformation marked shipped.

## Internal

- **CI** (`.github/workflows/ci.yml`) runs `cargo check`, `clippy -D warnings` and tests on every push and PR; the release workflow gates its builds on the same test job.
- Per-release notes: each release ships `release-notes/<tag>.md`; older cumulative notes were archived to `release-notes/archive-0.1.x.md`.
- Plugin loading split into a non-generic `LoadedPlugin` (library handle + dispatch) and `PluginDispatcher<T>` (typed response handling); a process-wide registry serves lookups to all request handlers.
- Shared `normalize_plugin_id` / `plugin_full_id` helpers in core enforce the hyphen convention; the CLI discovers built libraries by normalized name across both separator styles.
- The e2e suite runs single-threaded (`RUST_TEST_THREADS=1` in `.cargo/config.toml`) against a shared test database so `cargo test --workspace` passes from a fresh clone; upload fixtures are tracked in git.
- Warning cleanups across the workspace; rustfmt applied repo-wide.
