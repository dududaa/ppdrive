# v0.3.4 — Large Downloads Work Again

## Bug Fixes

- **`ppdrive plugin add` / `plugin update` no longer fail with `Error: failed to read download body: the response body is larger than request limit: 10485760`** — downloads read whole response bodies into memory through `ureq`'s 10MB default cap, but the shared media runtime bundle is 16.5MB, so installing any media plugin could not complete. Bodies are now streamed straight to disk with no size cap and flat memory use.
- **Partial downloads are cleaned up on failure** — an interrupted download removes its temporary file instead of leaving a truncated artifact behind.
- **`ppdrive update` release tarballs stream the same way** — fixing the same 10MB latent cap before server assets outgrow it.

## Upgrade Notes

- No configuration changes. From **v0.3.3** onward `ppdrive update` works as-is (v0.3.1/v0.3.2 updaters still hit the `Text file busy` bug fixed in v0.3.3 — migrate once by hand per those notes).

## Internal

- Workspace version moved to `0.3.4`.
- Shared `write_body_to_file` helper streams `ureq`'s unlimited body reader into a file and deletes it on error; tests cover a full write and mid-stream reader failure.
