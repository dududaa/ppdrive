# v0.3.5 — First Upload Into New Folders Works

## Bug Fixes

- **First upload into a bucket subdirectory no longer fails with `400 failed to resolve target path`** — the bucket containment check canonicalized the target path before the directory existed (and before `create_parents` could create it), so uploading e.g. `photos/2026/beach.jpg` as the first file into `photos/2026/` was rejected. The check now resolves against the nearest existing ancestor, so new files and directories upload cleanly.
- **`create_parents` now applies to bucket uploads** — parent directories were previously created only for uploads without a bucket, so even once the check passed a nested bucket upload would have failed at the final rename. The directory chain is now created before the file is moved into place, for bucket and non-bucket uploads alike.
- **Missing parent directories report `404 Parent directory does not exist`** (with `create_parents` off) instead of the misleading `400 failed to resolve target path`.

## Security

- Path containment is unchanged: uploads outside the target bucket still return `403`, and `..` traversal is still rejected with `400 path traversal detected`.

## Upgrade Notes

- No configuration changes — `ppdrive update` picks this up directly.

## Internal

- Workspace version moved to `0.3.5`.
- The bucket check now reuses the existing `canonicalize_loose` helper (already used by `media_streaming.output_dir` validation); parent creation moved above the bucket/non-bucket match in the completion path.
- New e2e coverage: first upload into a fresh nested bucket path with `create_parents` succeeds and writes the file; without it a missing parent returns 404.
