---
title: Secrets & Security
description: How PPDRIVE manages encryption keys and secrets.
---

PPDRIVE stores cryptographic secrets in a binary file and zeros memory on shutdown.

## Secrets File

Location: `.ppdrive_secret` in the same directory as the binaries.

### File Layout

The file is exactly **56 bytes**:

| Offset | Size | Purpose |
|---|---|---|
| 0–31 | 32 bytes | XChaCha20-Poly1305 encryption key |
| 32–55 | 24 bytes | XChaCha20 nonce |

### Initialization

The secrets file is created automatically on first run. If it doesn't exist, PPDRIVE generates cryptographically random keys and writes them to the file.

```sh
# Secrets are created when you first start the server or CLI
ppdrive serve
# .ppdrive_secret is created with mode 0600
```

### Permissions

On Unix systems, the file is created with mode `0600` (owner read/write only). If the file already exists, permissions are enforced on every read.

### Memory Safety

When the `AppSecrets` struct is dropped (e.g., on shutdown), all secret material is zeroed using `std::ptr::write_volatile` to minimize exposure in freed memory.

## What Each Key Is Used For

| Key | Usage |
|---|---|
| **Encryption key** (32 bytes) | Encrypts/decrypts client keys stored in the database |
| **Nonce** (24 bytes) | Used with the encryption key for XChaCha20-Poly1305 operations |

## Client Key Encryption

When a client is created:

1. A random 32-character hex key is generated
2. The key is encrypted with XChaCha20-Poly1305 using the app secret
3. The encrypted key, nonce, and a SHA-256 hash are stored in the database
4. The plaintext key is shown once to the operator (in the CLI output)

When a client token is verified:

1. The token is decrypted to recover the client key
2. The client key is hashed with SHA-256
3. The hash is looked up in the database to find the client ID

This design means client keys are never stored in plaintext in the database.

## Rotating Secrets

If `.ppdrive_secret` is deleted, PPDRIVE will generate new secrets on the next run. However, this will invalidate all existing client tokens and encrypted keys. You'll need to recreate clients.

```sh
# To rotate secrets (WARNING: invalidates all clients)
rm .ppdrive_secret
ppdrive serve  # New secrets are generated
ppdrive client create --name "New Client"  # Create new clients
```
