PPDRIVE supports two authentication methods: **client tokens** for API operations and **user tokens** for file permission management.

## How It Works

### Token Format

A client token is a hex-encoded string containing:

```
[24-byte nonce][encrypted client key]
```

The client key is encrypted with XChaCha20-Poly1305 using the application's secret key.

### Authentication Flow

1. Client sends a request with the token in a header
2. Server decrypts the token to recover the client key
3. Server hashes the client key with SHA-256
4. Server looks up the client ID by the hash
5. Server processes the request with the authenticated client ID

```
Client Request
  ↓
Header: x-ppdrive-client: <token>
  ↓
Decrypt token → client key
  ↓
SHA-256(client key) → hash
  ↓
Lookup client by hash → client ID
  ↓
Process request
```

### Header Name

The header name is configurable in `ppd_config.toml`:

```toml
client_header_key = "x-ppdrive-client"
```

Default: `x-ppdrive-client`

## Using the Token

Include the client token in the configured header for all API requests:

<Tabs>
<TabItem label="JavaScript">

```js
const CLIENT_TOKEN = "YOUR_CLIENT_TOKEN";

const res = await fetch("http://localhost:8000/upload/session", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "x-ppdrive-client": CLIENT_TOKEN,
  },
  body: JSON.stringify({ ... }),
});
```

</TabItem>
<TabItem label="curl">

```sh
curl -X POST http://localhost:8000/upload/session \
  -H "x-ppdrive-client: YOUR_CLIENT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ ... }'
```

</TabItem>
</Tabs>

## Token Rotation

Rotate a client's token with the CLI:

```sh
ppdrive client refresh --id <CLIENT_ID>
```

This:
1. Generates a new client key
2. Encrypts and stores it in the database
3. Returns a new token
4. The old token is immediately invalidated

## Which Endpoints Require Auth

| Endpoint | Auth Required | Method |
|---|---|---|
| `POST /buckets` | Client header | Create a bucket |
| `POST /upload/session` | Client header | Create upload session |
| `POST /upload/session/play/{payload}` | Signed token in URL | Upload chunk |
| `POST /download/sign` | Client header | Sign download URL |
| `GET /download/{token}` | Signed token in URL | Download file |
| `POST /buckets/{pid}/permissions` | Client or User header | Grant permission |
| `DELETE /buckets/{pid}/permissions` | Client or User header | Revoke permission |
| `GET /buckets/{pid}/permissions` | Client or User header | List permissions |

:::note
The download endpoint uses the signed token itself as authentication — no client header is needed.
:::

:::note
Permission endpoints accept either a client token (`x-ppdrive-client`) or a user token (`Authorization: Bearer <token>`).
:::

## Security Properties

- **Encrypted at rest** — Client keys are never stored in plaintext
- **Random nonces** — Each token encryption uses a fresh nonce
- **Rotatable** — Tokens can be rotated without recreating the client
- **Time-limited** — Upload and download tokens expire after a configurable duration
