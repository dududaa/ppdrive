Uploading is a two-step process: create a session, then send the file data.

## Overview

```
1. POST /upload/session    → Receive signed token
2. POST /upload/session/play/{token} → Upload file data
```

## Step 1: Create Upload Session

<Tabs>
<TabItem label="JavaScript">

```js
const CLIENT_TOKEN = "YOUR_TOKEN";

const res = await fetch("http://localhost:8000/upload/session", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "x-ppdrive-client": CLIENT_TOKEN,
  },
  body: JSON.stringify({
    asset_type: "File",
    path: "uploads/photos/avatar.jpg",
    target_filesize: 524288,
    expires: 120,
    bucket: "OPTIONAL_BUCKET_ID",
    content_type: "image/jpeg",
  }),
});

const { data: token } = await res.json();
```

</TabItem>
<TabItem label="curl">

```sh
curl -X POST http://localhost:8000/upload/session \
  -H "Content-Type: application/json" \
  -H "x-ppdrive-client: YOUR_TOKEN" \
  -d '{
    "asset_type": "File",
    "path": "uploads/photos/avatar.jpg",
    "target_filesize": 524288,
    "expires": 120,
    "bucket": "OPTIONAL_BUCKET_ID",
    "content_type": "image/jpeg"
  }'
```

</TabItem>
</Tabs>

### Request Body

| Field | Type | Required | Description |
|---|---|---|---|
| `asset_type` | `File` \| `Folder` | Yes | Type of asset |
| `path` | `String` | Yes | Target path (min 4 chars) |
| `expires` | `i64` | Yes | Token lifetime in seconds (30–86400) |
| `target_filesize` | `u64` | Files only | Expected file size in bytes |
| `create_parents` | `bool` | No | Create parent directories if missing |
| `overwrite` | `bool` | No | Overwrite existing file |
| `resumable` | `bool` | No | Enable chunked upload (requires Redis) |
| `bucket` | `String` | No | Bucket PID to upload into |
| `content_type` | `String` | If no bucket or bucket has accepts | MIME type of the file |
| `image_compression` | `Object` | No | Compress the image after upload — see [Image Compression](#image-compression) |
| `image_transformation` | `Object` | No | Transform the image after upload, before compression — see [Image Transformation](#image-transformation) |
| `audio_conversion` | `Object` | No | Convert the audio after upload — see [Audio Conversion](#audio-conversion) |
| `audio_effects` | `Object` | No | Apply audio effects after upload, before conversion — see [Audio Effects](#audio-effects) |

### Response

```json
{
  "data": "eyJ0eXAiOiJKV1..."
}
```

The `data` field contains a signed base64url token.

### Validation Rules

- Files >= 2 MB **must** use `resumable: true`
- `target_filesize` is required for file uploads
- `expires` must be between 30 and 86400 seconds (24 hours max)
- Unknown JSON fields are rejected (requests must not contain extra keys)
- Resumable uploads require Redis (`message_broker` in config)
- If `bucket` is specified, the client must own it
- If bucket has `accepts` restrictions, `content_type` is required
- If `bucket` is not provided, `content_type` is required for file uploads
- Without a bucket, the uploaded file's MIME type (inferred from its extension) must match the declared `content_type`
- `image_compression` requires `content_type` to be an `image/*` type and the `image_compression` plugin to be installed
- `image_compression.quality` must be 0–100; `width`/`height` must be ≥ 1 when given
- `image_transformation` requires `content_type` to be an `image/*` type and the `image_transformation` plugin to be installed
- `image_transformation.quality` must be 0–100; operation arguments are validated at session creation (see [Image Transformation](#image-transformation))
- `audio_conversion` requires `content_type` to be an `audio/*` type and the `audio_conversion` plugin to be installed
- `audio_conversion.quality` must be 0–100; `sample_rate` must be ≥ 1; `channels` must be 1 or 2
- `audio_effects` requires `content_type` to be an `audio/*` type and the `audio_effects` plugin to be installed
- `audio_effects.quality` must be 0–100; operation arguments are validated at session creation (see [Audio Effects](#audio-effects))
- Maximum 10,000 chunks per resumable upload

## Step 2: Upload File Data

<Tabs>
<TabItem label="JavaScript">

```js
const token = "eyJ0eXAiOiJKV1..."; // from Step 1
const file = /* your File object */;

const res = await fetch(`http://localhost:8000/upload/session/play/${token}`, {
  method: "POST",
  body: file,
});

const { data } = await res.json();
// data is null when complete, or a new token for resumable uploads
```

</TabItem>
<TabItem label="curl">

```sh
curl -X POST "http://localhost:8000/upload/session/play/eyJ0eXAiOiJKV1..." \
  --data-binary @/path/to/file.jpg
```

</TabItem>
</Tabs>

The token from Step 1 goes in the URL path. The file data goes in the request body.

### Response

```json
{
  "data": null
}
```

`null` means the upload is complete. For resumable uploads, a new token may be returned for the next chunk.

## Resumable Uploads

For large files, enable resumable uploads to send data in chunks:

<Tabs>
<TabItem label="JavaScript">

```js
// Step 1: Create session with resumable=true
const sessionRes = await fetch("http://localhost:8000/upload/session", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "x-ppdrive-client": CLIENT_TOKEN,
  },
  body: JSON.stringify({
    asset_type: "File",
    path: "uploads/large-video.mp4",
    target_filesize: 1073741824,
    expires: 120,
    resumable: true,
    bucket: "BUCKET_ID",
    content_type: "video/mp4",
  }),
});

let { data: token } = await sessionRes.json();

// Step 2: Send chunks
for (const chunk of chunks) {
  const res = await fetch(`http://localhost:8000/upload/session/play/${token}`, {
    method: "POST",
    body: chunk,
  });

  const { data } = await res.json();
  if (data === null) break; // upload complete
  token = data; // use new token for next chunk
}
```

</TabItem>
<TabItem label="curl">

```sh
# Step 1: Create session with resumable=true
curl -X POST http://localhost:8000/upload/session \
  -H "Content-Type: application/json" \
  -H "x-ppdrive-client: YOUR_TOKEN" \
  -d '{
    "asset_type": "File",
    "path": "uploads/large-video.mp4",
    "target_filesize": 1073741824,
    "expires": 120,
    "resumable": true,
    "bucket": "BUCKET_ID",
    "content_type": "video/mp4"
  }'

# Step 2: Send first chunk
curl -X POST "http://localhost:8000/upload/session/play/TOKEN" \
  --data-binary @chunk1.bin

# Response includes a new token for the next chunk
# { "data": "NEW_TOKEN..." }

# Step 3: Send next chunk with the new token
curl -X POST "http://localhost:8000/upload/session/play/NEW_TOKEN..." \
  --data-binary @chunk2.bin

# Repeat until complete
```

</TabItem>
</Tabs>

### How Resumable Uploads Work

1. Each chunk is appended to a temporary file
2. When the accumulated size reaches `target_filesize`, the file is moved to its final path
3. A new token is returned after each chunk with an incremented chunk index
4. Session state is cached in Redis with TTL matching the token expiration
5. If a chunk fails, you can resume from the last successful chunk using the latest token

## Uploading to a Bucket

When uploading to a bucket, the file path is relative to the bucket's root path:

```
Bucket path: storage/images
Upload path: avatar.jpg
Final location: storage/images/avatar.jpg
```

### Bucket Validations

At upload time, the server checks:
- **Ownership** — Client must own the bucket
- **Size limit** — Bucket size + file size must not exceed the bucket's max size
- **MIME type** — File type must match the bucket's `accepts` list (if configured)

## Uploading Without a Bucket

Files can be uploaded directly to a path without a bucket, but only if the target path starts with a [configured static directory](/configuration/config-file/#static-folders) in `ppd_config.toml`. Paths outside of configured static directories require a bucket.

The `content_type` field is **required** when uploading without a bucket. It declares the file's MIME type, and the server verifies it against the actual file (inferred from its extension) when the upload completes.

```js
  body: JSON.stringify({
    asset_type: "File",
    path: "uploads/documents/report.pdf",
    target_filesize: 102400,
    expires: 120,
    content_type: "application/pdf",
  }),
});

const { data: token } = await sessionRes.json();

await fetch(`http://localhost:8000/upload/session/play/${token}`, {
  method: "POST",

```

</TabItem>

The uploaded file's MIME type (inferred from the file extension) must match the declared `content_type`; a mismatch rejects the upload and removes the temporary file. No bucket ownership check is performed, but the upload will be rejected if the path doesn't start with a configured static directory.

## Image Compression

Provide `image_compression` in the session config to compress the file once the upload completes. Requires the `image_compression` plugin to be installed and an `image/*` `content_type`.

```json
{
  "asset_type": "File",
  "path": "uploads/photos/avatar.png",
  "target_filesize": 524288,
  "expires": 120,
  "content_type": "image/png",
  "image_compression": {
    "format": "WebP",
    "quality": 80,
    "width": 1600,
    "height": null,
    "background": false
  }
}
```

### Options

| Field | Type | Default | Description |
|---|---|---|---|
| `format` | `Jpeg` \| `Png` \| `WebP` \| `Avif` | `Jpeg` | Output format |
| `quality` | `u8` (0–100) | `80` | Compression quality |
| `width` | `u32` | `null` | Target width in pixels (≥ 1); `null` keeps the source width |
| `height` | `u32` | `null` | Target height in pixels (≥ 1); `null` keeps the source height |
| `background` | `bool` | `null` (see below) | Compress after responding (`true`) or inline (`false`) |

### Path rewriting

When the option is set, the server rewrites the target path's extension (and `content_type`) to match the requested `format` **at session creation** — e.g. `avatar.png` with `format: "WebP"` is stored as `avatar.webp` with `content_type: "image/webp"`. Overwrite checks, MIME validation and asset registration all use the rewritten path, so a bucket's `accepts` list must admit the *output* type.

### Inline vs background

- **Inline (default)** — compression runs before the final rename; the upload response returns only once the file exists at its target path. Compression failures fail the upload (`500`).
- **Background** — set `image_compression.background: true` per upload, or `image_compression_background = true` in `ppd_config.toml` (the per-upload option wins). The response is sent immediately after all bytes are received and validated; compression, rename and registration then run in a background task. Failures are logged server-side only — the client has already received a success response, and the file may briefly be missing at the target path.

## Image Transformation

Provide `image_transformation` in the session config to transform the file once the upload completes. When both options are set, transformation runs first and compression second, so compression's output format wins. Requires the `image_transformation` plugin to be installed and an `image/*` `content_type`.

```json
{
  "asset_type": "File",
  "path": "uploads/photos/avatar.png",
  "target_filesize": 524288,
  "expires": 120,
  "content_type": "image/png",
  "image_transformation": {
    "operations": [
      { "crop": { "x": 0, "y": 0, "width": 800, "height": 600 } },
      { "rotate": { "degrees": 90 } },
      { "adjust": { "brightness": 0.1, "contrast": 1.5, "saturation": 1.2 } },
      "grayscale"
    ],
    "custom_filters": null,
    "format": "WebP",
    "quality": 80,
    "background": false
  }
}
```

### Options

| Field | Type | Default | Description |
|---|---|---|---|
| `operations` | `Object[]` | `[]` | Typed operations applied in order — see below |
| `custom_filters` | `String` | `null` | Raw FFmpeg filter string appended after `operations` (must not contain NUL bytes) |
| `format` | `Jpeg` \| `Png` \| `WebP` \| `Avif` | `null` | Output format; `null` keeps the input format (no path rewrite) |
| `quality` | `u8` (0–100) | `null` (plugin default 80) | Encoder quality |
| `background` | `bool` | `null` (see below) | Transform after responding (`true`) or inline (`false`) |

### Operations

Each entry is tagged with its operation name; operations run in the order given.

| Operation | Fields | Description |
|---|---|---|
| `crop` | `x`, `y`, `width`, `height` (`u32`) | Extract a rectangle; bounds are checked against the source image, size must be non-zero |
| `rotate` | `degrees` (`u16`) | Rotate by 90, 180 or 270 |
| `flip` | `horizontal`, `vertical` (`bool`) | Mirror; at least one must be `true` |
| `pad` | `left`, `top`, `right`, `bottom` (`u32`), `color` (`String`) | Add a border; `color` is an FFmpeg color name or `#RRGGBB` |
| `grayscale` | — | Desaturate to gray |
| `adjust` | `brightness` (-1..=1), `contrast` (-1000..=1000), `saturation` (0..=3) (`f32`) | Color adjustment; values must be finite |
| `blur` | `sigma` (`f32`, must be > 0) | Gaussian blur |
| `sharpen` | `amount` (`f32`, must be finite) | Unsharp masking |
| `scale` | `width`, `height` (`u32`) | Exact resize; dimensions must be non-zero |

### Path rewriting

When `format` is set, the server rewrites the target path's extension (and `content_type`) to match it **at session creation** — exactly like compression (see above). With `format: null` nothing is rewritten and the output keeps the input format. When both options are set, the compression rewrite wins because compression runs last.

### Inline vs background

- **Inline (default)** — transformation runs before the final rename; the upload response returns only once the file exists at its target path. Transformation failures fail the upload (`500`).
- **Background** — set `image_transformation.background: true` per upload, or `image_transformation_background = true` in `ppd_config.toml` (the per-upload option wins). If either option requests background handling, the whole chain (transform → compress → rename → register) runs after the response; failures are logged server-side only, as described above.

## Audio Conversion

Provide `audio_conversion` in the session config to transcode the file once the upload completes. Requires the `audio_conversion` plugin to be installed and an `audio/*` `content_type`. The plugin needs FFmpeg shared libraries on the host — see the [plugin command](/cli/plugin/) for installation.

```json
{
  "asset_type": "File",
  "path": "uploads/audio/song.wav",
  "target_filesize": 10485760,
  "expires": 120,
  "content_type": "audio/wav",
  "audio_conversion": {
    "format": "Opus",
    "quality": 96,
    "sample_rate": 48000,
    "channels": 2,
    "background": false
  }
}
```

### Options

| Field | Type | Default | Description |
|---|---|---|---|
| `format` | `Wav` \| `Mp3` \| `Flac` \| `Aac` \| `Ogg` \| `Opus` | `Mp3` | Output format |
| `quality` | `u8` (0–100) | `80` | Encoding quality; ignored by the lossless `Wav`/`Flac` formats |
| `sample_rate` | `u32` | `null` | Target sample rate in Hz (≥ 1); `null` keeps the source rate |
| `channels` | `u8` (1 or 2) | `null` | Target channel count; `null` keeps mono/stereo and downmixes >2 to stereo |
| `background` | `bool` | `null` (see below) | Convert after responding (`true`) or inline (`false`) |

`quality` maps to a per-format bitrate ladder: MP3 32→320 kbps, AAC 64→256 kbps, Ogg 32→320 kbps and Opus 16→256 kbps across quality 0→100. Rates the target codec can't encode are snapped to the nearest supported one (Opus always encodes at 48 kHz).

### Path rewriting

When the option is set, the server rewrites the target path's extension (and `content_type`) to match the requested `format` **at session creation** — exactly like image compression (see above). Both Ogg Vorbis and Opus are stored with `content_type: "audio/ogg"`. Overwrite checks, MIME validation and asset registration all use the rewritten path, so a bucket's `accepts` list must admit the *output* type.

### Inline vs background

- **Inline (default)** — conversion runs before the final rename; the upload response returns only once the file exists at its target path. Conversion failures fail the upload (`500`).
- **Background** — set `audio_conversion.background: true` per upload, or `audio_conversion_background = true` in `ppd_config.toml` (the per-upload option wins). The response is sent immediately after all bytes are received and validated; conversion, rename and registration then run in a background task. Failures are logged server-side only — the client has already received a success response, and the file may briefly be missing at the target path.

## Audio Effects

Provide `audio_effects` in the session config to run an effect pass over the file once the upload completes. When both audio options are set, effects run first and conversion second, so conversion's output format wins. Requires the `audio_effects` plugin to be installed and an `audio/*` `content_type`.

```json
{
  "asset_type": "File",
  "path": "uploads/audio/song.mp3",
  "target_filesize": 10485760,
  "expires": 120,
  "content_type": "audio/mpeg",
  "audio_effects": {
    "operations": [
      { "volume": { "gain_db": -6.0 } },
      { "fade": { "fade_in_secs": 0.5, "fade_out_secs": 1.5 } },
      { "speed": { "factor": 1.25 } },
      { "normalize": { "target_lufs": -16.0 } }
    ],
    "custom_filters": null,
    "format": null,
    "quality": null,
    "background": false
  }
}
```

### Options

| Field | Type | Default | Description |
|---|---|---|---|
| `operations` | `Object[]` | `[]` | Typed operations applied in order — see below |
| `custom_filters` | `String` | `null` | Raw FFmpeg filter string appended after `operations` (must not contain NUL bytes) |
| `format` | `Wav` \| `Mp3` \| `Flac` \| `Aac` \| `Ogg` \| `Opus` | `null` | Output format; `null` writes `Wav` (the plugin default) — see path rewriting |
| `quality` | `u8` (0–100) | `null` (plugin default 80) | Encoder quality for the output format |
| `background` | `bool` | `null` (see below) | Process after responding (`true`) or inline (`false`) |

### Operations

Each entry is tagged with its operation name; operations run in the order given. Arguments are validated at session creation — invalid values are rejected before any file is received.

| Operation | Fields | Description |
|---|---|---|
| `volume` | `gain_db` (`f32`, finite) | Gain change in decibels |
| `fade` | `fade_in_secs`, `fade_out_secs` (`f32`, finite and ≥ 0) | Fade in at the start and/or fade out at the end, in seconds |
| `speed` | `factor` (`f32`, finite and > 0) | Playback speed; 2.0 = twice as fast, 0.5 = half speed. Must decompose into at most 16 `atempo` stages (roughly 8×10⁻⁶ – 1.3×10⁵) |
| `bass` | `gain_db`, `frequency`, `width` (`f32`, finite) | Low-shelf EQ; the plugin clamps gain to -900..=900, frequency to 0..=999999 and width to 0..=99999 |
| `treble` | `gain_db`, `frequency`, `width` (`f32`, finite) | High-shelf EQ; same clamps as `bass` |
| `echo` | `delay_ms` (`u32`, ≤ 60000), `decay` (`f32`, strictly between 0 and 1) | Single tap echo |
| `trim` | `start_secs`, `end_secs` (`f32`, finite, start ≥ 0, end > start) | Keep only `[start, end)` of the stream; alters the output duration |
| `reverse` | — | Play the stream backwards |
| `normalize` | `target_lufs` (`f32`, finite) | EBU R128 loudness normalisation; the plugin clamps the target to -70..=-5 |

### Path rewriting

Unlike image transformation, the effect pass always re-encodes: the server rewrites the target path's extension (and `content_type`) **at session creation** to the output format — the requested `format`, or `Wav` when `format` is omitted (`song.mp3` → `song.wav`, `content_type: "audio/wav"`). When `audio_conversion` is also set, its rewrite wins because conversion runs last.

### Inline vs background

- **Inline (default)** — the effect pass runs before the final rename; the upload response returns only once the file exists at its target path. Failures fail the upload (`500`).
- **Background** — set `audio_effects.background: true` per upload, or `audio_effects_background = true` in `ppd_config.toml` (the per-upload option wins). If either audio option requests background handling, the whole chain (effects → convert → rename → register) runs after the response; failures are logged server-side only, as described above.

## Rate Limits

- **100** requests per second per IP (burst up to 200)
- **50** concurrent requests per endpoint
- **2 MB** maximum request body size (per chunk)
- **30s** global request timeout (returns HTTP 408)

Rate limit headers are included in responses:
- `X-RateLimit-Limit` — Maximum requests per second
- `X-RateLimit-Remaining` — Requests remaining in the current window
- `X-RateLimit-Retry-After` — Seconds until the rate limit resets

## Private Bucket Assets

When a file is uploaded to a **private bucket**, it is automatically registered as an asset. The uploader is granted **admin** permission on the file.

This means:
- The uploader can always access their own files
- The uploader can grant read/write/admin permissions to other clients or users
- Permission checks are enforced when signing download URLs

For public buckets, no asset registration occurs — files are accessible to everyone.

See [File Permissions](/api/permissions/) for details on managing file-level access.
