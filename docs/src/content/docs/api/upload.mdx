Uploading is a two-step process: create a session, then send the file data.

## Overview

```
1. POST /upload/session    → Receive signed token
2. POST /upload/session/play/{token} → Upload file data
```

## Step 1: Create Upload Session

<Tabs>
<TabItem label="JavaScript">

```js
const CLIENT_TOKEN = "YOUR_TOKEN";

const res = await fetch("http://localhost:8000/upload/session", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "x-ppdrive-client": CLIENT_TOKEN,
  },
  body: JSON.stringify({
    asset_type: "File",
    path: "uploads/photos/avatar.jpg",
    target_filesize: 524288,
    expires: 120,
    bucket: "OPTIONAL_BUCKET_ID",
    content_type: "image/jpeg",
  }),
});

const { data: token } = await res.json();
```

</TabItem>
<TabItem label="curl">

```sh
curl -X POST http://localhost:8000/upload/session \
  -H "Content-Type: application/json" \
  -H "x-ppdrive-client: YOUR_TOKEN" \
  -d '{
    "asset_type": "File",
    "path": "uploads/photos/avatar.jpg",
    "target_filesize": 524288,
    "expires": 120,
    "bucket": "OPTIONAL_BUCKET_ID",
    "content_type": "image/jpeg"
  }'
```

</TabItem>
</Tabs>

### Request Body

| Field | Type | Required | Description |
|---|---|---|---|
| `asset_type` | `File` \| `Folder` | Yes | Type of asset |
| `path` | `String` | Yes | Target path (min 4 chars) |
| `expires` | `i64` | Yes | Token lifetime in seconds (30–86400) |
| `target_filesize` | `u64` | Files only | Expected file size in bytes |
| `create_parents` | `bool` | No | Create parent directories if missing |
| `overwrite` | `bool` | No | Overwrite existing file |
| `resumable` | `bool` | No | Enable chunked upload (requires Redis) |
| `bucket` | `String` | No | Bucket PID to upload into |
| `content_type` | `String` | If no bucket or bucket has accepts | MIME type of the file |
| `image_conversion` | `Object` | No | Convert the image after upload — see [Image Conversion](#image-conversion) |
| `image_transformation` | `Object` | No | Transform the image after upload, before conversion — see [Image Transformation](#image-transformation) |
| `audio_conversion` | `Object` | No | Convert the audio after upload — see [Audio Conversion](#audio-conversion) |
| `audio_effects` | `Object` | No | Apply audio effects after upload, before conversion — see [Audio Effects](#audio-effects) |
| `video_conversion` | `Object` | No | Convert the video after upload — see [Video Conversion](#video-conversion) |
| `video_transformation` | `Object` | No | Transform the video after upload, before conversion — see [Video Transformation](#video-transformation) |
| `media_streaming` | `Object` | No | Package the file into an HLS/DASH stream after upload — see [Media Streaming](#media-streaming) |

### Response

```json
{
  "data": "eyJ0eXAiOiJKV1..."
}
```

The `data` field contains a signed base64url token.

### Validation Rules

- Files >= 2 MB **must** use `resumable: true`
- `target_filesize` is required for file uploads
- `expires` must be between 30 and 86400 seconds (24 hours max)
- Unknown JSON fields are rejected (requests must not contain extra keys)
- Resumable uploads require Redis (`message_broker` in config)
- If `bucket` is specified, the client must own it
- If bucket has `accepts` restrictions, `content_type` is required
- If `bucket` is not provided, `content_type` is required for file uploads
- Without a bucket, the uploaded file's MIME type (inferred from its extension) must match the declared `content_type`
- `image_conversion` requires `content_type` to be an `image/*` type and the `image_conversion` plugin to be installed
- `image_conversion.quality` must be 0–100; `width`/`height` must be ≥ 1 when given; `effort` must be 0–100; `max_bytes` must be ≥ 1; `scale` must be finite and > 0
- `image_transformation` requires `content_type` to be an `image/*` type and the `image_transformation` plugin to be installed
- `image_transformation.quality` must be 0–100; operation arguments are validated at session creation (see [Image Transformation](#image-transformation))
- `audio_conversion` requires `content_type` to be an `audio/*` type and the `audio_conversion` plugin to be installed
- `audio_conversion.quality` must be 0–100; `sample_rate` must be ≥ 1; `channels` must be 1 or 2
- `audio_effects` requires `content_type` to be an `audio/*` type and the `audio_effects` plugin to be installed
- `audio_effects.quality` must be 0–100; operation arguments are validated at session creation (see [Audio Effects](#audio-effects))
- `video_conversion` requires `content_type` to be a `video/*` type and the `video_conversion` plugin to be installed
- `video_conversion.quality` and `effort` must be 0–100; `width`/`height` must be ≥ 1 when given; `max_bytes` must be ≥ 1; `fps` must be 1–1000; `keyframe_interval` must be ≥ 1; `scale` must be finite and > 0
- `video_transformation` requires `content_type` to be a `video/*` type and the `video_transformation` plugin to be installed
- `video_transformation.quality` must be 0–100; operation arguments are validated at session creation (see [Video Transformation](#video-transformation))
- `media_streaming` requires `content_type` to be a `video/*` or `audio/*` type and the `media-streaming` plugin to be installed
- `media_streaming.segment_duration` must be 1–30; `quality` must be 0–100; `renditions` must be non-empty when given, with `width`/`height` ≥ 1, `quality` ≤ 100, `bitrate` ≥ 1 and a finite positive `scale`
- `media_streaming.output_dir` is resolved like `path` (no `..`, inside the server root and the bucket) and must not contain the upload path
- Maximum 10,000 chunks per resumable upload

## Step 2: Upload File Data

<Tabs>
<TabItem label="JavaScript">

```js
const token = "eyJ0eXAiOiJKV1..."; // from Step 1
const file = /* your File object */;

const res = await fetch(`http://localhost:8000/upload/session/play/${token}`, {
  method: "POST",
  body: file,
});

const { data } = await res.json();
// data is null when complete, or a new token for resumable uploads
```

</TabItem>
<TabItem label="curl">

```sh
curl -X POST "http://localhost:8000/upload/session/play/eyJ0eXAiOiJKV1..." \
  --data-binary @/path/to/file.jpg
```

</TabItem>
</Tabs>

The token from Step 1 goes in the URL path. The file data goes in the request body.

### Response

```json
{
  "data": null
}
```

`null` means the upload is complete. For resumable uploads, a new token may be returned for the next chunk.

## Resumable Uploads

For large files, enable resumable uploads to send data in chunks:

<Tabs>
<TabItem label="JavaScript">

```js
// Step 1: Create session with resumable=true
const sessionRes = await fetch("http://localhost:8000/upload/session", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "x-ppdrive-client": CLIENT_TOKEN,
  },
  body: JSON.stringify({
    asset_type: "File",
    path: "uploads/large-video.mp4",
    target_filesize: 1073741824,
    expires: 120,
    resumable: true,
    bucket: "BUCKET_ID",
    content_type: "video/mp4",
  }),
});

let { data: token } = await sessionRes.json();

// Step 2: Send chunks
for (const chunk of chunks) {
  const res = await fetch(`http://localhost:8000/upload/session/play/${token}`, {
    method: "POST",
    body: chunk,
  });

  const { data } = await res.json();
  if (data === null) break; // upload complete
  token = data; // use new token for next chunk
}
```

</TabItem>
<TabItem label="curl">

```sh
# Step 1: Create session with resumable=true
curl -X POST http://localhost:8000/upload/session \
  -H "Content-Type: application/json" \
  -H "x-ppdrive-client: YOUR_TOKEN" \
  -d '{
    "asset_type": "File",
    "path": "uploads/large-video.mp4",
    "target_filesize": 1073741824,
    "expires": 120,
    "resumable": true,
    "bucket": "BUCKET_ID",
    "content_type": "video/mp4"
  }'

# Step 2: Send first chunk
curl -X POST "http://localhost:8000/upload/session/play/TOKEN" \
  --data-binary @chunk1.bin

# Response includes a new token for the next chunk
# { "data": "NEW_TOKEN..." }

# Step 3: Send next chunk with the new token
curl -X POST "http://localhost:8000/upload/session/play/NEW_TOKEN..." \
  --data-binary @chunk2.bin

# Repeat until complete
```

</TabItem>
</Tabs>

### How Resumable Uploads Work

1. Each chunk is appended to a temporary file
2. When the accumulated size reaches `target_filesize`, the file is moved to its final path
3. A new token is returned after each chunk with an incremented chunk index
4. Session state is cached in Redis with TTL matching the token expiration
5. If a chunk fails, you can resume from the last successful chunk using the latest token

## Uploading to a Bucket

When uploading to a bucket, the file path is relative to the bucket's root path:

```
Bucket path: storage/images
Upload path: avatar.jpg
Final location: storage/images/avatar.jpg
```

### Bucket Validations

At upload time, the server checks:
- **Ownership** — Client must own the bucket
- **Size limit** — Bucket size + file size must not exceed the bucket's max size
- **MIME type** — File type must match the bucket's `accepts` list (if configured)

## Uploading Without a Bucket

Files can be uploaded directly to a path without a bucket, but only if the target path starts with a [configured static directory](/configuration/config-file/#static-folders) in `ppd_config.toml`. Paths outside of configured static directories require a bucket.

The `content_type` field is **required** when uploading without a bucket. It declares the file's MIME type, and the server verifies it against the actual file (inferred from its extension) when the upload completes.

<Tabs>
<TabItem label="JavaScript">

```js
const sessionRes = await fetch("http://localhost:8000/upload/session", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "x-ppdrive-client": CLIENT_TOKEN,
  },
  body: JSON.stringify({
    asset_type: "File",
    path: "uploads/documents/report.pdf",
    target_filesize: 102400,
    expires: 120,
    content_type: "application/pdf",
  }),
});

const { data: token } = await sessionRes.json();

await fetch(`http://localhost:8000/upload/session/play/${token}`, {
  method: "POST",
  body: file,
});
```

</TabItem>
<TabItem label="curl">

```sh
curl -X POST http://localhost:8000/upload/session \
  -H "Content-Type: application/json" \
  -H "x-ppdrive-client: YOUR_TOKEN" \
  -d '{
    "asset_type": "File",
    "path": "uploads/documents/report.pdf",
    "target_filesize": 102400,
    "expires": 120,
    "content_type": "application/pdf"
  }'
```

</TabItem>
</Tabs>

The uploaded file's MIME type (inferred from the file extension) must match the declared `content_type`; a mismatch rejects the upload and removes the temporary file. No bucket ownership check is performed, but the upload will be rejected if the path doesn't start with a configured static directory.

## Image Conversion

Provide `image_conversion` in the session config to convert the file once the upload completes. Requires the `image-conversion` plugin to be installed and an `image/*` `content_type`.

```json
{
  "asset_type": "File",
  "path": "uploads/photos/avatar.png",
  "target_filesize": 524288,
  "expires": 120,
  "content_type": "image/png",
  "image_conversion": {
    "format": "WebP",
    "quality": 80,
    "width": 1600,
    "height": null,
    "background": false
  }
}
```

### Options

| Field | Type | Default | Description |
|---|---|---|---|
| `format` | `Jpeg` \| `Png` \| `WebP` \| `Avif` | `Jpeg` | Output format |
| `quality` | `u8` (0–100) | `80` | Output quality |
| `width` | `u32` | `null` | Target width in pixels (≥ 1); `null` keeps the source width |
| `height` | `u32` | `null` | Target height in pixels (≥ 1); `null` keeps the source height |
| `scale` | `f32` | `null` | Proportional resize, applied only when both `width` and `height` are `null`; must be finite and > 0 |
| `effort` | `u8` (0–100) | `null` | Encoding effort (AVIF only) |
| `max_bytes` | `u64` | `null` | Output size budget in bytes (≥ 1); the encoder lowers quality until the file fits |
| `background` | `bool` | `null` (see below) | Convert after responding (`true`) or inline (`false`) |

### Path rewriting

When the option is set, the server rewrites the target path's extension (and `content_type`) to match the requested `format` **at session creation** — e.g. `avatar.png` with `format: "WebP"` is stored as `avatar.webp` with `content_type: "image/webp"`. Overwrite checks, MIME validation and asset registration all use the rewritten path, so a bucket's `accepts` list must admit the *output* type.

### Inline vs background

- **Inline (default)** — conversion runs before the final rename; the upload response returns only once the file exists at its target path. Conversion failures fail the upload (`500`).
- **Background** — set `image_conversion.background: true` per upload, or `image_conversion_background = true` in `ppd_config.toml` (the per-upload option wins). The response is sent immediately after all bytes are received and validated; conversion, rename and registration then run in a background task. Failures are logged server-side only — the client has already received a success response, and the file may briefly be missing at the target path.

## Image Transformation

Provide `image_transformation` in the session config to transform the file once the upload completes. When both options are set, transformation runs first and conversion second, so conversion's output format wins. Requires the `image_transformation` plugin to be installed and an `image/*` `content_type`.

```json
{
  "asset_type": "File",
  "path": "uploads/photos/avatar.png",
  "target_filesize": 524288,
  "expires": 120,
  "content_type": "image/png",
  "image_transformation": {
    "operations": [
      { "crop": { "x": 0, "y": 0, "width": 800, "height": 600 } },
      { "rotate": { "degrees": 90 } },
      { "adjust": { "brightness": 0.1, "contrast": 1.5, "saturation": 1.2 } },
      "grayscale"
    ],
    "custom_filters": null,
    "format": "WebP",
    "quality": 80,
    "background": false
  }
}
```

### Options

| Field | Type | Default | Description |
|---|---|---|---|
| `operations` | `Object[]` | `[]` | Typed operations applied in order — see below |
| `custom_filters` | `String` | `null` | Raw FFmpeg filter string appended after `operations` (must not contain NUL bytes) |
| `format` | `Jpeg` \| `Png` \| `WebP` \| `Avif` | `null` | Output format; `null` keeps the input format (no path rewrite) |
| `quality` | `u8` (0–100) | `null` (plugin default 80) | Encoder quality |
| `background` | `bool` | `null` (see below) | Transform after responding (`true`) or inline (`false`) |

### Operations

Each entry is tagged with its operation name; operations run in the order given.

| Operation | Fields | Description |
|---|---|---|
| `crop` | `x`, `y`, `width`, `height` (`u32`) | Extract a rectangle; bounds are checked against the source image, size must be non-zero |
| `rotate` | `degrees` (`u16`) | Rotate by 90, 180 or 270 |
| `flip` | `horizontal`, `vertical` (`bool`) | Mirror; at least one must be `true` |
| `pad` | `left`, `top`, `right`, `bottom` (`u32`), `color` (`String`) | Add a border; `color` is an FFmpeg color name or `#RRGGBB` |
| `grayscale` | — | Desaturate to gray |
| `adjust` | `brightness` (-1..=1), `contrast` (-1000..=1000), `saturation` (0..=3) (`f32`) | Color adjustment; values must be finite |
| `blur` | `sigma` (`f32`, must be > 0) | Gaussian blur |
| `sharpen` | `amount` (`f32`, must be finite) | Unsharp masking |
| `scale` | `width`, `height` (`u32`) | Exact resize; dimensions must be non-zero |

### Path rewriting

When `format` is set, the server rewrites the target path's extension (and `content_type`) to match it **at session creation** — exactly like image conversion (see above). With `format: null` nothing is rewritten and the output keeps the input format. When both options are set, the conversion rewrite wins because conversion runs last.

### Inline vs background

- **Inline (default)** — transformation runs before the final rename; the upload response returns only once the file exists at its target path. Transformation failures fail the upload (`500`).
- **Background** — set `image_transformation.background: true` per upload, or `image_transformation_background = true` in `ppd_config.toml` (the per-upload option wins). If either option requests background handling, the whole chain (transform → convert → rename → register) runs after the response; failures are logged server-side only, as described above.

## Audio Conversion

Provide `audio_conversion` in the session config to transcode the file once the upload completes. Requires the `audio_conversion` plugin to be installed and an `audio/*` `content_type`. The plugin needs FFmpeg shared libraries on the host — see the [plugin command](/cli/plugin/) for installation.

```json
{
  "asset_type": "File",
  "path": "uploads/audio/song.wav",
  "target_filesize": 10485760,
  "expires": 120,
  "content_type": "audio/wav",
  "audio_conversion": {
    "format": "Opus",
    "quality": 96,
    "sample_rate": 48000,
    "channels": 2,
    "background": false
  }
}
```

### Options

| Field | Type | Default | Description |
|---|---|---|---|
| `format` | `Wav` \| `Mp3` \| `Flac` \| `Aac` \| `Ogg` \| `Opus` | `Mp3` | Output format |
| `quality` | `u8` (0–100) | `80` | Encoding quality; ignored by the lossless `Wav`/`Flac` formats |
| `sample_rate` | `u32` | `null` | Target sample rate in Hz (≥ 1); `null` keeps the source rate |
| `channels` | `u8` (1 or 2) | `null` | Target channel count; `null` keeps mono/stereo and downmixes >2 to stereo |
| `background` | `bool` | `null` (see below) | Convert after responding (`true`) or inline (`false`) |

`quality` maps to a per-format bitrate ladder: MP3 32→320 kbps, AAC 64→256 kbps, Ogg 32→320 kbps and Opus 16→256 kbps across quality 0→100. Rates the target codec can't encode are snapped to the nearest supported one (Opus always encodes at 48 kHz).

### Path rewriting

When the option is set, the server rewrites the target path's extension (and `content_type`) to match the requested `format` **at session creation** — exactly like image conversion (see above). Both Ogg Vorbis and Opus are stored with `content_type: "audio/ogg"`. Overwrite checks, MIME validation and asset registration all use the rewritten path, so a bucket's `accepts` list must admit the *output* type.

### Inline vs background

- **Inline (default)** — conversion runs before the final rename; the upload response returns only once the file exists at its target path. Conversion failures fail the upload (`500`).
- **Background** — set `audio_conversion.background: true` per upload, or `audio_conversion_background = true` in `ppd_config.toml` (the per-upload option wins). The response is sent immediately after all bytes are received and validated; conversion, rename and registration then run in a background task. Failures are logged server-side only — the client has already received a success response, and the file may briefly be missing at the target path.

## Audio Effects

Provide `audio_effects` in the session config to run an effect pass over the file once the upload completes. When both audio options are set, effects run first and conversion second, so conversion's output format wins. Requires the `audio_effects` plugin to be installed and an `audio/*` `content_type`.

```json
{
  "asset_type": "File",
  "path": "uploads/audio/song.mp3",
  "target_filesize": 10485760,
  "expires": 120,
  "content_type": "audio/mpeg",
  "audio_effects": {
    "operations": [
      { "volume": { "gain_db": -6.0 } },
      { "fade": { "fade_in_secs": 0.5, "fade_out_secs": 1.5 } },
      { "speed": { "factor": 1.25 } },
      { "normalize": { "target_lufs": -16.0 } }
    ],
    "custom_filters": null,
    "format": null,
    "quality": null,
    "background": false
  }
}
```

### Options

| Field | Type | Default | Description |
|---|---|---|---|
| `operations` | `Object[]` | `[]` | Typed operations applied in order — see below |
| `custom_filters` | `String` | `null` | Raw FFmpeg filter string appended after `operations` (must not contain NUL bytes) |
| `format` | `Wav` \| `Mp3` \| `Flac` \| `Aac` \| `Ogg` \| `Opus` | `null` | Output format; `null` writes `Wav` (the plugin default) — see path rewriting |
| `quality` | `u8` (0–100) | `null` (plugin default 80) | Encoder quality for the output format |
| `background` | `bool` | `null` (see below) | Process after responding (`true`) or inline (`false`) |

### Operations

Each entry is tagged with its operation name; operations run in the order given. Arguments are validated at session creation — invalid values are rejected before any file is received.

| Operation | Fields | Description |
|---|---|---|
| `volume` | `gain_db` (`f32`, finite) | Gain change in decibels |
| `fade` | `fade_in_secs`, `fade_out_secs` (`f32`, finite and ≥ 0) | Fade in at the start and/or fade out at the end, in seconds |
| `speed` | `factor` (`f32`, finite and > 0) | Playback speed; 2.0 = twice as fast, 0.5 = half speed. Must decompose into at most 16 `atempo` stages (roughly 8×10⁻⁶ – 1.3×10⁵) |
| `bass` | `gain_db`, `frequency`, `width` (`f32`, finite) | Low-shelf EQ; the plugin clamps gain to -900..=900, frequency to 0..=999999 and width to 0..=99999 |
| `treble` | `gain_db`, `frequency`, `width` (`f32`, finite) | High-shelf EQ; same clamps as `bass` |
| `echo` | `delay_ms` (`u32`, ≤ 60000), `decay` (`f32`, strictly between 0 and 1) | Single tap echo |
| `trim` | `start_secs`, `end_secs` (`f32`, finite, start ≥ 0, end > start) | Keep only `[start, end)` of the stream; alters the output duration |
| `reverse` | — | Play the stream backwards |
| `normalize` | `target_lufs` (`f32`, finite) | EBU R128 loudness normalisation; the plugin clamps the target to -70..=-5 |

### Path rewriting

Unlike image transformation, the effect pass always re-encodes: the server rewrites the target path's extension (and `content_type`) **at session creation** to the output format — the requested `format`, or `Wav` when `format` is omitted (`song.mp3` → `song.wav`, `content_type: "audio/wav"`). When `audio_conversion` is also set, its rewrite wins because conversion runs last.

### Inline vs background

- **Inline (default)** — the effect pass runs before the final rename; the upload response returns only once the file exists at its target path. Failures fail the upload (`500`).
- **Background** — set `audio_effects.background: true` per upload, or `audio_effects_background = true` in `ppd_config.toml` (the per-upload option wins). If either audio option requests background handling, the whole chain (effects → convert → rename → register) runs after the response; failures are logged server-side only, as described above.

## Video Conversion

Provide `video_conversion` in the session config to transcode the file once the upload completes. Requires the `video_conversion` plugin to be installed and a `video/*` `content_type`. The plugin needs FFmpeg shared libraries on the host — see the [plugin command](/cli/plugin/) for installation.

```json
{
  "asset_type": "File",
  "path": "uploads/video/clip.avi",
  "target_filesize": 52428800,
  "expires": 300,
  "content_type": "video/x-msvideo",
  "video_conversion": {
    "format": "Mp4",
    "quality": 80,
    "width": 1280,
    "background": false
  }
}
```

### Options

| Field | Type | Default | Description |
|---|---|---|---|
| `format` | `Mp4` \| `WebM` \| `Mov` \| `Mkv` \| `Avi` \| `Mp4Av1` \| `WebMAv1` \| `MkvAv1` \| `Mp4Hevc` \| `MovHevc` | `Mp4` | Output container/codec (H.264, VP9, AV1 or H.265) |
| `quality` | `u8` (0–100) | `80` | Encoding quality, mapped to the encoder's CRF scale |
| `width` | `u32` | `null` | Target width in pixels (≥ 1); with only `height`, the other side keeps the aspect ratio |
| `height` | `u32` | `null` | Target height in pixels (≥ 1); with only `width`, the other side keeps the aspect ratio |
| `scale` | `f32` | `null` | Proportional resize factor, applied only when both `width` and `height` are `null`; must be finite and > 0 |
| `effort` | `u8` (0–100) | `null` | Encoder effort |
| `max_bytes` | `u64` | `null` | Maximum output size in bytes (≥ 1); the encoder lowers quality until the output fits |
| `fps` | `u32` (1–1000) | `null` | Constant output frame rate; `null` keeps the source timing |
| `drop_audio` | `bool` | `false` | Drop the source audio track instead of stream-copying it |
| `keyframe_interval` | `u32` | `null` | Maximum keyframe distance in frames (≥ 1); `null` keeps the encoder default GOP |
| `background` | `bool` | `null` (see below) | Convert after responding (`true`) or inline (`false`) |

### Path rewriting

When the option is set, the server rewrites the target path's extension (and `content_type`) to match the requested `format` **at session creation** — exactly like image/audio conversion. Overwrite checks, MIME validation and asset registration all use the rewritten path, so a bucket's `accepts` list must admit the *output* type.

### Inline vs background

- **Inline (default)** — conversion runs before the final rename; the upload response returns only once the file exists at its target path. Conversion failures fail the upload (`500`).
- **Background** — set `video_conversion.background: true` per upload, or `video_conversion_background = true` in `ppd_config.toml` (the per-upload option wins). The response is sent immediately after all bytes are received and validated; conversion, rename and registration then run in a background task. Failures are logged server-side only, as described above.

## Video Transformation

Provide `video_transformation` in the session config to run a filter pass over the file once the upload completes. When both video options are set, transformation runs first and conversion second, so conversion's output format wins. Requires the `video_transformation` plugin to be installed and a `video/*` `content_type`.

```json
{
  "asset_type": "File",
  "path": "uploads/video/clip.mp4",
  "target_filesize": 52428800,
  "expires": 300,
  "content_type": "video/mp4",
  "video_transformation": {
    "operations": [
      { "crop": { "x": 0, "y": 0, "width": 1280, "height": 720 } },
      { "scale": { "width": 640, "height": 360 } },
      { "rotate": { "degrees": 90 } }
    ],
    "custom_filters": null,
    "format": null,
    "quality": null,
    "background": false
  }
}
```

### Options

| Field | Type | Default | Description |
|---|---|---|---|
| `operations` | `Object[]` | `[]` | Typed operations applied in order — see below |
| `custom_filters` | `String` | `null` | Raw FFmpeg filter string appended after `operations` (must not contain NUL bytes) |
| `format` | `Mp4` \| `WebM` \| `Mov` \| `Mkv` \| `Avi` \| `Mp4Av1` \| `WebMAv1` \| `MkvAv1` \| `Mp4Hevc` \| `MovHevc` | `null` | Output container; `null` keeps the input container when it is MP4/MOV/WebM/Matroska (otherwise the plugin falls back to `Mp4`) |
| `quality` | `u8` (0–100) | `null` (plugin default 80) | Encoder quality for the output format |
| `background` | `bool` | `null` (see below) | Process after responding (`true`) or inline (`false`) |

### Operations

Each entry is tagged with its operation name; operations run in the order given. Arguments are validated at session creation — invalid values are rejected before any file is received.

| Operation | Fields | Description |
|---|---|---|
| `crop` | `x`, `y`, `width`, `height` (`u32`, non-zero) | Extract a rectangle; bounds are validated against the source frame when the plugin runs |
| `scale` | `width`, `height` (`u32`, non-zero) | Exact resize |
| `rotate` | `degrees` (90, 180 or 270) | Lossless rotation via transpose passes |
| `flip` | `horizontal`, `vertical` (`bool`, at least one true) | Mirror the frame (both = 180° via flips) |
| `grayscale` | — | Desaturate to gray |
| `adjust` | `brightness` (-1..=1), `contrast` (-1000..=1000), `saturation` (0..=3), all finite | Color adjustment |
| `blur` | `sigma` (`f32`, finite and > 0) | Gaussian blur |
| `sharpen` | `amount` (`f32`, finite) | Unsharp masking; the plugin clamps to -2..=5 |
| `pad` | `left`, `top`, `right`, `bottom` (`u32`), `color` (non-empty FFmpeg color name or `#RRGGBB`) | Add a painted border |
| `trim` | `start` (`f64`, finite and ≥ 0), `duration` (`f64`, finite and > 0, optional) | Keep only `[start, start + duration)` of the source timeline; also applies to the audio track |
| `speed` | `factor` (`f64`, finite and > 0) | Change playback speed; the audio track is dropped |
| `reverse` | — | Play the video backwards; the audio track is dropped and clips whose frame buffering would exceed 1 GiB are rejected |

### Path rewriting

The pass always re-encodes. When `format` is set, the server rewrites the target path's extension (and `content_type`) **at session creation** to that format — exactly like image transformation. When `format` is omitted the input container is kept (MP4/MOV/WebM/Matroska; anything else falls back to MP4 by the plugin) and the path is left unchanged. When `video_conversion` is also set, its rewrite wins because conversion runs last.

### Inline vs background

- **Inline (default)** — the filter pass runs before the final rename; the upload response returns only once the file exists at its target path. Failures fail the upload (`500`).
- **Background** — set `video_transformation.background: true` per upload, or `video_transformation_background = true` in `ppd_config.toml` (the per-upload option wins). If either video option requests background handling, the whole chain (transform → convert → rename → register) runs after the response; failures are logged server-side only, as described above.

## Media Streaming

Provide `media_streaming` in the session config to package the uploaded file into an adaptive HLS or DASH stream once the upload completes. Unlike the other post-processing options the plugin is **file-based**: one call writes the master playlist plus every segment into an output directory. Packaging runs last — after any in-place conversion and the rename — and requires the `media-streaming` plugin to be installed and a `video/*` or `audio/*` `content_type` (video inputs become an adaptive ladder, audio-only inputs a single audio rendition).

```json
{
  "asset_type": "File",
  "path": "videos/clip.mp4",
  "target_filesize": 5242880,
  "expires": 300,
  "content_type": "video/mp4",
  "media_streaming": {
    "protocol": "hls",
    "segment_duration": 4,
    "quality": 80,
    "output_dir": "streams/clip",
    "delete_source": false,
    "background": false
  }
}
```

### Options

| Field | Type | Default | Description |
|---|---|---|---|
| `protocol` | `hls` \| `dash` | `hls` | `hls` writes `master.m3u8` + variant playlists over MPEG-TS segments; `dash` writes `manifest.mpd` over fragmented-MP4 segments |
| `segment_duration` | `u32` (1–30) | `4` | Target seconds per segment |
| `quality` | `u8` (0–100) | `80` | Base encoder quality for every rendition (and the shared AAC audio track) |
| `renditions` | `Array` | `null` (auto) | Explicit ladder; `null` derives one from the source resolution (never upscales). Each rung takes `width`, `height`, `scale`, `quality` and `bitrate`: explicit dimensions win, `scale` applies when both are `None`, and `bitrate` feeds the playlist's bandwidth attribute |
| `output_dir` | `String` | `null` (sidecar) | Output directory for the package, relative to the server root — the same bucket rules as `path` apply. `null` writes beside the upload into `<path>.stream/` |
| `delete_source` | `bool` | `true` | Delete the source file once the package is written; the registered asset path then points at the master playlist |
| `background` | `bool` | `null` (see below) | Package after responding (`true`) or inline (`false`) |

### Output directory and bucket rules

`output_dir` is resolved against the server root exactly like `path`: `..` components are rejected and — when a bucket is used — the directory must resolve inside the bucket. The sidecar default (`<path>.stream`) sits beside the file, so it inherits the same containment automatically. `output_dir` must not contain the upload path — packaging would wipe the source before reading it. An existing package directory is replaced on re-upload.

### Serving the package

Public buckets serve the package automatically: playlists and segments are plain files under the bucket's mount. Private buckets register only one asset (the source file, or the master playlist when `delete_source` is on) — HLS/DASH clients resolve relative segment URLs, so on-the-fly streaming pairs best with public buckets.

### Inline vs background

- **Inline (default)** — packaging runs after the rename; the upload response returns only once the package exists at its target directory. Failures fail the upload (`500`) and the source file is kept.
- **Background** — set `media_streaming.background: true` per upload, or `media_streaming_background = true` in `ppd_config.toml` (the per-upload option wins). If any post-processing option requests background handling, the whole chain (process → rename → package → register) runs after the response; failures are logged server-side only, as described above.

## Rate Limits

- **100** requests per second per IP (burst up to 200)
- **50** concurrent requests per endpoint
- **2 MB** maximum request body size (per chunk)
- **30s** global request timeout (returns HTTP 408)

Rate limit headers are included in responses:
- `x-ratelimit-limit` — Burst capacity allowed for the client
- `x-ratelimit-remaining` — Requests remaining in the current window
- `retry-after` — (HTTP 429 only) Seconds until the rate limit resets, mirrored as `x-ratelimit-after`

## Private Bucket Assets

When a file is uploaded to a **private bucket**, it is automatically registered as an asset. The uploader is granted **admin** permission on the file.

This means:
- The uploader can always access their own files
- The uploader can grant read/write/admin permissions to other clients or users
- Permission checks are enforced when signing download URLs

For public buckets, no asset registration occurs — files are accessible to everyone.

See [File Permissions](/api/permissions/) for details on managing file-level access.
