PPDRIVE supports two download methods: direct access for public buckets and signed URLs for private buckets.

## Public Buckets And Static Folders

Files in public buckets and configured static folders are served directly via HTTP. No authentication required.

<Tabs>
<TabItem label="JavaScript">

```js
const res = await fetch("http://localhost:8000/storage/images/photo.jpg");
const blob = await res.blob();
```

</TabItem>
<TabItem label="curl">

```sh
curl http://localhost:8000/storage/images/photo.jpg
```

</TabItem>
</Tabs>

The server auto-detects the `Content-Type` from the file extension.

## Private Buckets

Private buckets require a signed download URL. This is a two-step process.

### Step 1: Sign the Download

<Tabs>
<TabItem label="JavaScript">

```js
const CLIENT_TOKEN = "YOUR_TOKEN";
const BUCKET_PID = "BUCKET_PID";

const res = await fetch("http://localhost:8000/download/sign", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "x-ppdrive-client": CLIENT_TOKEN,
  },
  body: JSON.stringify({
    path: "photo.jpg",
    bucket: BUCKET_PID,
    expires: 300,
  }),
});

const { data: token } = await res.json();
```

</TabItem>
<TabItem label="curl">

```sh
curl -X POST http://localhost:8000/download/sign \
  -H "Content-Type: application/json" \
  -H "x-ppdrive-client: YOUR_TOKEN" \
  -d '{
    "path": "photo.jpg",
    "bucket": "BUCKET_PID",
    "expires": 300
  }'
```

</TabItem>
</Tabs>

#### Request Body

| Field | Type | Required | Description |
|---|---|---|---|
| `path` | `String` | Yes | File path relative to the bucket |
| `bucket` | `String` | Yes | Bucket PID |
| `expires` | `i64` | Yes | Token lifetime in seconds (30–3600) |

#### Response

```json
{
  "data": "eyJ0eXAiOiJKV1..."
}
```

### Step 2: Download the File

<Tabs>
<TabItem label="JavaScript">

```js
const token = "eyJ0eXAiOiJKV1..."; // from Step 1

const res = await fetch(`http://localhost:8000/download/${token}`);
const blob = await res.blob();

// Save to file (Node.js)
// const fs = require("fs");
// fs.writeFileSync("photo.jpg", Buffer.from(await res.arrayBuffer()));
```

</TabItem>
<TabItem label="curl">

```sh
curl "http://localhost:8000/download/eyJ0eXAiOiJKV1..." --output photo.jpg
```

</TabItem>
</Tabs>

No client header is needed — the signed token itself is the authentication.

## Range Requests

The download endpoint supports HTTP Range requests for partial content:

<Tabs>
<TabItem label="JavaScript">

```js
const token = "eyJ0eXAiOiJKV1...";

// Download first 1024 bytes
const res = await fetch(`http://localhost:8000/download/${token}`, {
  headers: { Range: "bytes=0-1023" },
});

// res.status === 206 for partial content
const blob = await res.blob();
```

</TabItem>
<TabItem label="curl">

```sh
# Download first 1024 bytes
curl "http://localhost:8000/download/TOKEN" \
  -H "Range: bytes=0-1023" \
  --output partial.bin

# Download last 1024 bytes
curl "http://localhost:8000/download/TOKEN" \
  -H "Range: bytes=-1024" \
  --output tail.bin
```

</TabItem>
</Tabs>

### Range Response Headers

For partial content (HTTP 206):

```
HTTP/1.1 206 Partial Content
Content-Type: image/jpeg
Content-Length: 1024
Content-Range: bytes 0-1023/524288
Accept-Ranges: bytes
```

### Range Status Codes

| Status | Meaning |
|---|---|
| 200 | Full file (no Range header) |
| 206 | Partial content (valid Range) |
| 416 | Range not satisfiable |

## Sign Validation

When signing a download URL, the server validates:

1. **Bucket exists** — Returns 404 if bucket PID is invalid
2. **Bucket is private** — Returns 400 if bucket is public (use direct URL instead)
3. **Client owns bucket** — Returns 403 if client doesn't have access
4. **Path is within bucket** — Returns 403 if path escapes the bucket
5. **File exists** — Returns 404 if file is not on disk

## Download Token Verification

When serving the file, the server:

1. Decodes the base64url token
2. Decrypts the client key from the database
3. Verifies the hash signature
4. Checks the token hasn't expired
5. Resolves and serves the file

## Example: Full Flow

<Tabs>
<TabItem label="JavaScript">

```js
// 1. Sign the download
const signRes = await fetch("http://localhost:8000/download/sign", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "x-ppdrive-client": CLIENT_TOKEN,
  },
  body: JSON.stringify({
    path: "report.pdf",
    bucket: BUCKET_PID,
    expires: 300,
  }),
});

const { data: token } = await signRes.json();

// 2. Download the file
const fileRes = await fetch(`http://localhost:8000/download/${token}`);
const buffer = Buffer.from(await fileRes.arrayBuffer());
require("fs").writeFileSync("report.pdf", buffer);
```

</TabItem>
<TabItem label="curl">

```sh
# 1. Sign download
TOKEN=$(curl -s -X POST http://localhost:8000/download/sign \
  -H "Content-Type: application/json" \
  -H "x-ppdrive-client: abc123..." \
  -d '{"path":"report.pdf","bucket":"BUCKET_PID","expires":300}' \
  | jq -r '.data')

# 2. Download
curl "http://localhost:8000/download/$TOKEN" --output report.pdf
```

</TabItem>
</Tabs>

## Error Responses

| Status | Message | Cause |
|---|---|---|
| 400 | `path contains invalid components: '..' is not allowed` | Path traversal attempt (contains `..`) |
| 401 | `download token expired` | Token has passed its expiration |
| 401 | `...` (verification error) | Token is invalid or tampered |
| 403 | `path escapes storage root` | Canonicalized path escapes storage |
| 404 | `file not found` | File doesn't exist on disk |
| 408 | `Request Timeout` | Server did not receive a complete request within 30 seconds |
| 416 | `Range not satisfiable` | Invalid Range header |
