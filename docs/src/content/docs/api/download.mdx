PPDRIVE supports two download methods: direct access for public buckets and signed URLs for private buckets.

## Public Buckets And Static Folders

Files in public buckets and configured static folders are served directly via HTTP. No authentication required.

<Tabs>
<TabItem label="JavaScript">

```js
const res = await fetch("http://localhost:8000/storage/images/photo.jpg");
const blob = await res.blob();
```

</TabItem>
<TabItem label="curl">

```sh
curl http://localhost:8000/storage/images/photo.jpg
```

</TabItem>
</Tabs>

The server auto-detects the `Content-Type` from the file extension.

### Transformations on Direct Downloads

Append an `image_transformation` query parameter (URL-encoded JSON, the same [configuration shape](/api/upload/#image-transformation) as uploads) to receive an on-the-fly rendition instead of the original file:

<Tabs>
<TabItem label="JavaScript">

```js
const config = { operations: [{ rotate: { degrees: 90 } }], format: "WebP" };
const query = encodeURIComponent(JSON.stringify(config));

const res = await fetch(
  `http://localhost:8000/storage/images/photo.jpg?image_transformation=${query}`,
);
const blob = await res.blob();
```

</TabItem>
<TabItem label="curl">

```sh
curl -G http://localhost:8000/storage/images/photo.jpg \
  --data-urlencode 'image_transformation={"operations":["grayscale"]}' \
  --output gray.jpg
```

</TabItem>
</Tabs>

- The `image_transformation` plugin must be installed, and the source file must be an image (`image/*`).
- `custom_filters` is rejected with `400` on this unauthenticated surface — use typed `operations` only.
- Only `GET` requests carrying the parameter are transformed; every other request passes through to the original file unchanged.

## Private Buckets

Private buckets require a signed download URL. This is a two-step process.

### Step 1: Sign the Download

<Tabs>
<TabItem label="JavaScript">

```js
const CLIENT_TOKEN = "YOUR_TOKEN";
const BUCKET_PID = "BUCKET_PID";

const res = await fetch("http://localhost:8000/download/sign", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "x-ppdrive-client": CLIENT_TOKEN,
  },
  body: JSON.stringify({
    path: "photo.jpg",
    bucket: BUCKET_PID,
    expires: 300,
  }),
});

const { data: token } = await res.json();
```

</TabItem>
<TabItem label="curl">

```sh
curl -X POST http://localhost:8000/download/sign \
  -H "Content-Type: application/json" \
  -H "x-ppdrive-client: YOUR_TOKEN" \
  -d '{
    "path": "photo.jpg",
    "bucket": "BUCKET_PID",
    "expires": 300
  }'
```

</TabItem>
</Tabs>

#### Request Body

| Field | Type | Required | Description |
|---|---|---|---|
| `path` | `String` | Yes | File path relative to the bucket |
| `bucket` | `String` | Yes | Bucket PID |
| `expires` | `i64` | Yes | Token lifetime in seconds (30–3600) |
| `image_transformation` | `Object` | No | Serve an on-the-fly rendition when the token is used — see [Image Transformation](#image-transformation) |

When `image_transformation` is included, the server validates it **at sign time** (before the bucket lookup): operation arguments, the `image/*` source requirement, and plugin availability. The configuration is embedded in the signed token, so every download with that token serves the rendition.

#### Response

```json
{
  "data": "eyJ0eXAiOiJKV1..."
}
```

### Step 2: Download the File

<Tabs>
<TabItem label="JavaScript">

```js
const token = "eyJ0eXAiOiJKV1..."; // from Step 1

const res = await fetch(`http://localhost:8000/download/${token}`);
const blob = await res.blob();

// Save to file (Node.js)
// const fs = require("fs");
// fs.writeFileSync("photo.jpg", Buffer.from(await res.arrayBuffer()));
```

</TabItem>
<TabItem label="curl">

```sh
curl "http://localhost:8000/download/eyJ0eXAiOiJKV1..." --output photo.jpg
```

</TabItem>
</Tabs>

No client header is needed — the signed token itself is the authentication.

## Range Requests

The download endpoint supports HTTP Range requests for partial content:

<Tabs>
<TabItem label="JavaScript">

```js
const token = "eyJ0eXAiOiJKV1...";

// Download first 1024 bytes
const res = await fetch(`http://localhost:8000/download/${token}`, {
  headers: { Range: "bytes=0-1023" },
});

// res.status === 206 for partial content
const blob = await res.blob();
```

</TabItem>
<TabItem label="curl">

```sh
# Download first 1024 bytes
curl "http://localhost:8000/download/TOKEN" \
  -H "Range: bytes=0-1023" \
  --output partial.bin

# Download last 1024 bytes
curl "http://localhost:8000/download/TOKEN" \
  -H "Range: bytes=-1024" \
  --output tail.bin
```

</TabItem>
</Tabs>

### Range Response Headers

For partial content (HTTP 206):

```
HTTP/1.1 206 Partial Content
Content-Type: image/jpeg
Content-Length: 1024
Content-Range: bytes 0-1023/524288
Accept-Ranges: bytes
```

### Range Status Codes

| Status | Meaning |
|---|---|
| 200 | Full file (no Range header) |
| 206 | Partial content (valid Range) |
| 416 | Range not satisfiable |

## Image Transformation

Both download surfaces can apply the `image_transformation` plugin on the fly (requires the plugin to be installed). See [Image Transformation](/api/upload/#image-transformation) for the full options and operations reference.

- **Signed downloads** — pass `image_transformation` in the [sign request](#step-1-sign-the-download); it is validated at sign time and embedded in the token.
- **Direct downloads** — append `?image_transformation=<url-encoded JSON>` as shown [above](#transformations-on-direct-downloads).

A transformed response is always a full `200` — the `Range` header does not apply to a re-encoded rendition and is ignored.

### Caching

Transformed downloads are cacheable at two levels:

- **HTTP revalidation** — every transformed response carries an `ETag` derived from the source file (path, size and modification time) and the requested configuration. Send it back with `If-None-Match` to receive `304 Not Modified` without running the plugin.
- **Server-side cache** — when `message_broker` is configured, rendered renditions are stored in Redis under the same key. The TTL is `transform_cache_ttl_secs` (default `86400`; `0` disables server-side caching). Without a reachable broker the cache is simply skipped — downloads never fail because of caching.

`Cache-Control: max-age` defaults to `transform_cache_max_age_secs` (default `3600`); for signed downloads it is capped at the token's remaining lifetime.

## Sign Validation

When signing a download URL, the server validates:

1. **Bucket exists** — Returns 404 if bucket PID is invalid
2. **Bucket is private** — Returns 400 if bucket is public (use direct URL instead)
3. **Client owns bucket or has file permission** — Returns 403 if no access
4. **Path is within bucket** — Returns 403 if path escapes the bucket
5. **File exists** — Returns 404 if file is not on disk

:::note
For private buckets, access is granted if the requester is the bucket owner **or** has at least **read** permission on the file. See [File Permissions](/api/permissions/) for details.
:::

## Download Token Verification

When serving the file, the server:

1. Decodes the base64url token
2. Decrypts the client key from the database
3. Verifies the hash signature
4. Checks the token hasn't expired
5. Resolves and serves the file

## Example: Full Flow

<Tabs>
<TabItem label="JavaScript">

```js
// 1. Sign the download
const signRes = await fetch("http://localhost:8000/download/sign", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "x-ppdrive-client": CLIENT_TOKEN,
  },
  body: JSON.stringify({
    path: "report.pdf",
    bucket: BUCKET_PID,
    expires: 300,
  }),
});

const { data: token } = await signRes.json();

// 2. Download the file
const fileRes = await fetch(`http://localhost:8000/download/${token}`);
const buffer = Buffer.from(await fileRes.arrayBuffer());
require("fs").writeFileSync("report.pdf", buffer);
```

</TabItem>
<TabItem label="curl">

```sh
# 1. Sign download
TOKEN=$(curl -s -X POST http://localhost:8000/download/sign \
  -H "Content-Type: application/json" \
  -H "x-ppdrive-client: abc123..." \
  -d '{"path":"report.pdf","bucket":"BUCKET_PID","expires":300}' \
  | jq -r '.data')

# 2. Download
curl "http://localhost:8000/download/$TOKEN" --output report.pdf
```

</TabItem>
</Tabs>

## Error Responses

| Status | Message | Cause |
|---|---|---|
| 400 | `path contains invalid components: '..' is not allowed` | Path traversal attempt (contains `..`) |
| 400 | `image_transformation operation #N (...): ...` | Invalid transformation operation arguments |
| 400 | `image_transformation requires an image/* file, got '...'` | Transformation source is not an image |
| 400 | `image-transformation plugin is not installed` | Transformation requested but the plugin is missing or failed to load |
| 400 | `custom_filters is not allowed for direct downloads` | Raw FFmpeg filter string on the public query surface |
| 400 | `invalid image_transformation: ...` | Malformed transformation JSON in the query string |
| 401 | `download token expired` | Token has passed its expiration |
| 401 | `...` (verification error) | Token is invalid or tampered |
| 403 | `path escapes storage root` | Canonicalized path escapes storage |
| 404 | `file not found` | File doesn't exist on disk |
| 408 | `Request Timeout` | Server did not receive a complete request within 30 seconds |
| 416 | `Range not satisfiable` | Invalid Range header |
