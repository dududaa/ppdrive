---
title: Download Flow
description: How to download files from public and private buckets.
---

PPDRIVE supports two download methods: direct access for public buckets and signed URLs for private buckets.

## Public Buckets

Files in public buckets are served directly via HTTP. No authentication required.

```sh
curl http://localhost:8000/storage/images/photo.jpg
```

The server auto-detects the `Content-Type` from the file extension.

## Private Buckets

Private buckets require a signed download URL. This is a two-step process.

### Step 1: Sign the Download

```sh
curl -X POST http://localhost:8000/download/sign \
  -H "Content-Type: application/json" \
  -H "x-ppdrive-client: YOUR_TOKEN" \
  -d '{
    "path": "photo.jpg",
    "bucket": "BUCKET_PID",
    "expires": 300
  }'
```

#### Request Body

| Field | Type | Required | Description |
|---|---|---|---|
| `path` | `String` | Yes | File path relative to the bucket |
| `bucket` | `String` | Yes | Bucket PID |
| `expires` | `i64` | Yes | Token lifetime in seconds (30–3600) |

#### Response

```json
{
  "data": "eyJ0eXAiOiJKV1..."
}
```

### Step 2: Download the File

```sh
curl "http://localhost:8000/download/eyJ0eXAiOiJKV1..." --output photo.jpg
```

No client header is needed — the signed token itself is the authentication.

## Range Requests

The download endpoint supports HTTP Range requests for partial content:

```sh
# Download first 1024 bytes
curl "http://localhost:8000/download/TOKEN" \
  -H "Range: bytes=0-1023" \
  --output partial.bin

# Download last 1024 bytes
curl "http://localhost:8000/download/TOKEN" \
  -H "Range: bytes=-1024" \
  --output tail.bin
```

### Range Response Headers

For partial content (HTTP 206):

```
HTTP/1.1 206 Partial Content
Content-Type: image/jpeg
Content-Length: 1024
Content-Range: bytes 0-1023/524288
Accept-Ranges: bytes
```

### Range Status Codes

| Status | Meaning |
|---|---|
| 200 | Full file (no Range header) |
| 206 | Partial content (valid Range) |
| 416 | Range not satisfiable |

## Sign Validation

When signing a download URL, the server validates:

1. **Bucket exists** — Returns 404 if bucket PID is invalid
2. **Bucket is private** — Returns 400 if bucket is public (use direct URL instead)
3. **Client owns bucket** — Returns 403 if client doesn't have access
4. **Path is within bucket** — Returns 403 if path escapes the bucket
5. **File exists** — Returns 404 if file is not on disk

## Download Token Verification

When serving the file, the server:

1. Decodes the base64url token
2. Decrypts the client key from the database
3. Verifies the hash signature
4. Checks the token hasn't expired
5. Resolves and serves the file

## Example: Full Flow

```sh
# 1. Create client
ppdrive client create --name "Download Client"
# → Client Token: abc123...

# 2. Create private bucket
ppdrive bucket create \
  --name private-docs \
  --path storage/private \
  --owner-type client \
  --owner-id CLIENT_ID

# 3. Upload a file
# (See Upload Flow guide)

# 4. Sign download
TOKEN=$(curl -s -X POST http://localhost:8000/download/sign \
  -H "Content-Type: application/json" \
  -H "x-ppdrive-client: abc123..." \
  -d '{"path":"report.pdf","bucket":"BUCKET_PID","expires":300}' \
  | jq -r '.data')

# 5. Download
curl "http://localhost:8000/download/$TOKEN" --output report.pdf
```

## Error Responses

| Status | Message | Cause |
|---|---|---|
| 401 | `download token expired` | Token has passed its expiration |
| 401 | `...` (verification error) | Token is invalid or tampered |
| 403 | `path escapes storage root` | Path traversal attempt |
| 404 | `file not found` | File doesn't exist on disk |
| 416 | `Range not satisfiable` | Invalid Range header |
