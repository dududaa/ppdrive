Plugins extend the server with dynamically loaded native libraries — the dashboard UI, image compression, image transformation, audio conversion and audio effects ship as plugins. Plugin commands work without a database or config file.

## Install a Plugin

```sh
ppdrive plugin add <ID> --source <SOURCE> [OPTIONS]
```

### Arguments

| Flag | Required | Description |
|---|---|---|
| `<ID>` | Yes | Plugin id. The `ppdrive-` prefix is implied: `dashboard` installs `ppdrive-dashboard` |
| `--source` | Yes | Where to install from — see [Sources](#sources) |
| `--version` | No | Release version to install (default: `latest`) |
| `--local` | No | Install from a local library file or local Rust source directory |
| `--build` | No | Build from source with `cargo build --release --lib --package ppdrive-<id>` |

### Sources

| Mode | `--source` value | What happens |
|---|---|---|
| Remote, default | `github:owner/repo`, `owner/repo` or `https://github.com/owner/repo` | Downloads the release asset `ppdrive-<id>-<os>-<arch>.<ext>` from the repository's GitHub releases |
| Remote + `--build` | Same as above | Downloads the source archive for the release tag and compiles it with cargo |
| Remote git URL | A `.git` URL | Requires `--build` — clones and compiles the repository |
| Local library (`--local`) | Path to a `.so` / `.dylib` / `.dll` file | Copies the library into `libs/` |
| Local source (`--local --build`) | Path to a Rust source directory | Compiles with cargo and copies the built library |

### Example

```sh
# Install from a remote repository, building the plugin from source
ppdrive plugin add image_compression --source github:owner/image-compression --build

# Install a prebuilt release asset (media plugins ship from ppdrive-media)
ppdrive plugin add audio_conversion --source github:dududaa/ppdrive-media

# Install a prebuilt local library
ppdrive plugin add dashboard --source ./ppdrive-dashboard-linux-x86_64.so --local

# Build and install from a local source directory
ppdrive plugin add dashboard --source ~/src/dashboard/router --local --build
```

:::note
Restart the server (`ppdrive serve`) after installing or updating a plugin — plugins are loaded at startup.
:::

## Activate and Deactivate Plugins

Every installed plugin is **active** by default. The server loads only active plugins at startup; deactivating a plugin keeps it installed (and updatable) but unloaded.

```sh
ppdrive plugin activate <ID>
ppdrive plugin deactivate <ID>
```

`<ID>` may be short (`dashboard`) or full (`ppdrive-dashboard`). The new state is persisted to the registry — restart the server to apply it. Until an activated plugin's library loads, or after deactivation, requests that need it fail with a message naming the state:

```
image-transformation plugin is installed but deactivated; run `ppdrive plugin activate image-transformation`
```

Updating a plugin preserves its activation state.

## List Installed Plugins

```sh
ppdrive plugin list
```

### Output

```
ID                            VERSION    SOURCE                                  ACTIVE    INSTALLED
---------------------------------------------------------------------------------------------------------
ppdrive-dashboard             local      github:owner/dashboard                  yes       2026-09-26T10:41:12Z
```

The `SOURCE` recorded at install time is where `ppdrive plugin update` re-fetches from. `ACTIVE` shows whether the server loads the plugin (`yes`/`no`) — see [Activate and Deactivate Plugins](#activate-and-deactivate-plugins).

## Remove a Plugin

```sh
ppdrive plugin remove <ID>
```

`<ID>` may be short (`dashboard`) or full (`ppdrive-dashboard`). The registry entry and the library file under `libs/` are deleted. Restart the server to stop serving it.

## Update Plugins

```sh
ppdrive plugin update [<ID>]
```

| Argument | Description |
|---|---|
| `<ID>` | Plugin to update (prefix optional). Omit to update **all** installed plugins |

Update re-fetches from the plugin's recorded source: remote plugins are re-installed from the **latest** release (compiled when the plugin was installed with `--build`, downloaded as a release asset otherwise); local plugins are rebuilt from their recorded source directory, or re-copied from the recorded library path.

### Example

```sh
# Update one plugin
ppdrive plugin update image_compression

# Update everything
ppdrive plugin update
```

## How It Works

- The registry lives at `plugins.json` in the PPDRIVE root directory (next to the binaries); library files live in `libs/`.
- Ids are hyphenated throughout: the stored short id (`dashboard`), the full id (`ppdrive-dashboard`), the cargo package name (`ppdrive-dashboard`) and the artifact base name (`ppdrive-dashboard-linux-x86_64.so`). The legacy `ppdrive_`/`_` forms are still accepted on input and normalized.
- The server loads every **active** registered plugin at startup and keeps the libraries loaded for the process lifetime; deactivated plugins are skipped until reactivated.
